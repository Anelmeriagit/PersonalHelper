# Сессия и вход (читать при правках входа, сессии, cookie, лимитов, привязки Telegram на уровне ключей)

- Мультипользовательский вход (этап 1, 2026-10-04): аккаунты в Redis, `api/_acc.js` + `api/auth.js` (`logout`, действия с сессией и вход через Google одним эндпоинтом; привязка Telegram — `api/tglink.js`). Входа по паролю и регистрации нет (гостевой режим, части 1 и 3): ни формы на сайте, ни действий `login`/`register`, ни никнейма, пароля и scrypt в коде. Аккаунты, созданные раньше с никнеймом и паролем (поля `nick`, `pw`, ключ `nick:<никнейм>`), код не читает; их удаляет разовый скрипт `scripts/purge-pw.mjs` (сухой прогон по умолчанию), `deleteAccount` убирает ключ `nick:` такого аккаунта.
- Лимиты: всего аккаунтов `MAX_USERS` (по умолчанию 500), 20 возвратов от Google в час с адреса. Ключи Redis с префиксом `DB_PREFIX`.
- Вход через Google (этап 5, часть 3, 2026-10-07): `GET /api/auth?action=google` (переход на Google: код, `state`, `nonce`, PKCE S256, состояние в подписанной cookie `cb_oauth` на 10 минут, Redis не трогает) и `GET /api/auth?action=google-cb` (обмен кода на сервере, проверка `id_token`, поиск или создание аккаунта по `sub`, `cb_session`, переход на `/`; при отказе или ошибке переход на `/?gerr=<код>`). Переменные `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Аккаунт Google: `gid:<sub>` → id и `acc:<id>` = `{gsub, at, email?}` без `nick` и `pw`. Лимит 20 возвратов в час с адреса (`rl:g:ip:*`). Подробности, коды `gerr` и пределы — `notes/account.md`.
- Сессия: cookie `cb_session` хранит id аккаунта (32 hex), подпись HMAC только от `SESSION_SECRET` (≥32 символов), 30 дней со скользящим продлением. Смена `SESSION_VERSION` разлогинивает все устройства. `AUTH_HASH` больше не используется. Сайт без сессии (401 при открытии) работает гостем; конец сессии на ходу (401 раздела) возвращает в гостевой режим без экрана входа: данные аккаунта из памяти (кэшбэк, агент, WiFi) заменяют гостевые, несохранённые правки остаются в них.
- Кэшбэк, напоминания, агент, WiFi и состояние бота личные: эндпоинты работают только с аккаунтом из сессии. Переменные `WIFI_*` больше не читаются.
- `AUTH_USER` код больше не читает; переменную удалить из Vercel после подтверждения владельца (`notes/CHECKLIST.md`).
- Привязка Telegram (этап 3a, 2026-10-04; с 3b от неё зависят рассылка и ответы бота): на вкладке «Напоминания» блок «Telegram»; `POST /api/tglink` выдаёт одноразовую ссылку `https://t.me/<бот>?start=<токен>` (10 минут, не больше 5 ссылок за 10 минут на аккаунт), бот по `/start <токен>` связывает Telegram с аккаунтом. Один Telegram привязан к одному аккаунту. Ключи Redis (с `DB_PREFIX`): `tgt:<хеш токена>` → id аккаунта (TTL), `tgp:<id>` → хеш последней ссылки, `tg:<id>` → `{tid, chat, un, at}`, `tgu:<tid>` → id аккаунта, `tgs` → множество id аккаунтов с привязкой (обход для cron). Токен нигде не хранится, только sha256. Функции в `api/_acc.js`: `createLinkToken`, `bindTelegram`, `getLink`, `unlinkTelegram`, `accountOfTelegram`, `linkedIds`. Подробности — `notes/reminders.md`.
