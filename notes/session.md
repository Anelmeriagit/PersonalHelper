# Сессия и вход (читать при правках входа, сессии, cookie, лимитов, ключей привязки Telegram и соединения)

## Модель
- Вход один: Google (`notes/account.md`). Входа по паролю, регистрации, никнеймов нет; поля `nick`, `pw` и ключ `nick:<ник>` старых аккаунтов код не читает (на боевой базе их нет, по словам владельца, сухой прогон 2026-10-08 показал 0); `deleteAccount` на всякий случай убирает `nick:`.
- Без сессии сайт работает гостем (`notes/guest.md`); 401 на ходу возвращает в гостевой режим без экрана входа. Кэшбэк, напоминания, агент, Wi-Fi и состояние бота личные: эндпоинты работают только с аккаунтом из сессии.
- Не читаются и удалены из Vercel (по словам владельца, 2026-10-13): `AUTH_USER`, `AUTH_HASH`, `WIFI_*`.

## Cookie и лимиты
- `cb_session`: id аккаунта (32 hex) и срок, подпись HMAC только от `SESSION_SECRET` (≥32 символов); `HttpOnly; Secure; SameSite=Strict`, 30 дней, продлевается `renewCookie` (`api/_lib.js`, вызывается из `GET /api/data`). Смена `SESSION_VERSION` разлогинивает все устройства.
- Всего аккаунтов `MAX_USERS` (по умолчанию 500, счётчик `users`). Возвраты от Google: 20 в час с адреса (`rl:g:ip:<хеш>`). Привязка Telegram: 5 новых ссылок за 10 минут на аккаунт (`rl:tgl:<id>`). Соединение: 5 новых ссылок (`rl:pl:<id>`) и 10 попыток (`rl:pj:<id>`) за 10 минут. Счётчики `rl:*` временные и в копию не идут.

## Привязка Telegram (ключи; поведение — `notes/reminders.md`)
Блок «Telegram» на «Напоминаниях»: `POST /api/tglink` даёт одноразовую ссылку `https://t.me/<бот>?start=<токен>` (10 минут), бот по `/start <токен>` связывает чат с аккаунтом; один Telegram — один аккаунт. Ключи: `tgt:<sha256 токена>` → id аккаунта (TTL), `tgp:<id>` → хеш последней ссылки, `tg:<id>` → `{tid, chat, un, at}`, `tgu:<tid>` → id аккаунта, `tgs` → множество id с привязкой (обход при перестройке `dueq`). Сам токен не хранится. Функции `api/_acc.js`: `createLinkToken`, `bindTelegram`, `getLink`, `unlinkTelegram`, `accountOfTelegram`, `linkedIds`.

## Соединение аккаунтов (ключи; поведение — `notes/account.md`)
`pair:<id>` → id второго аккаунта, без срока; пара верна только при `pair:A = B` и `pair:B = A` и существующем аккаунте B (`partnerOf`). `cnt:<sha256 токена>` → id давшего ссылку (TTL 24 часа), `cnp:<id>` → хеш последней ссылки (новая гасит прежнюю).
