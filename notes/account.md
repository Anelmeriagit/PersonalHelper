- **Окно «Настройки аккаунта»** (`#acctDlg`, по центру): «Отображаемое имя» (имя и справа «Изменить»; правка на месте: до 32 символов, пустое имя возвращает «Helper User»), «Email» (или «не указан»), «Account ID», «Telegram» (только если привязан: «ID …», при наличии `@имя`, справа «Отвязать» с подтверждением), «Соединить аккаунты» (пока кнопка «Скоро» недоступна), красный блок с кнопкой «ПЕРМАНЕНТНОЕ УДАЛЕНИЕ АККАУНТА». После удаления: экран входа и сообщение «Аккаунт удалён».
- Значения с сервера (имя, email, id, Telegram) выводятся через `esc()` или `textContent`.

## Контракт API (для серверной части; лимит функций: всё в существующем `api/auth.js`, новый файл не нужен)
- `GET /api/data` → добавить `name` (строка, `''` если не задано). Аккаунт там уже читается (`nickOf`), так что дополнительных команд Redis нет. Окно настроек читает остальное только при открытии (`me`: чтение аккаунта и привязки Telegram), это сделано намеренно ради лимита команд Upstash.
- `POST /api/auth {action:'me'}` → `{id, name, email, tg:{linked, id, username}}`; `id` — id аккаунта (32 hex, `crypto.randomBytes(16)`, уникальность гарантирует запись `NX`; у аккаунтов Google тот же генератор), `tg.id` — Telegram user id (`tid`), `email` пустой у аккаунтов с паролем. 401 без сессии.
- `POST /api/auth {action:'rename', name}` → `{name}`. Сервер сам обрезает пробелы, не больше 32 символов, без управляющих символов; `''` сбрасывает имя.
- `POST /api/auth {action:'delete', confirm:'удалить'}` → `{ok:true}` и сброс cookie. Удалить все ключи аккаунта (`acc`, `nick`, `doc`, `rem`, `agent`, `wifi`, `bot`, `tg`, `tgu`, `tgs`, лимиты), только через функции `_acc.js` / `_lib.js`. Слово проверять и на сервере.
- Отвязка в окне настроек использует существующий `DELETE /api/tglink`.
- Вход через Google: `GET /api/auth?action=google` перенаправляет на Google (код авторизации, `state` и PKCE в короткой cookie), обратный адрес `GET /api/auth?action=google-cb` создаёт или находит аккаунт по `sub` Google, ставит `cb_session`, ведёт на `/`. Переменные окружения (только имена): `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

## Решения и допущения
- Кнопка Google сделана переходом по ссылке, а не скриптом Google Identity Services: тот требует внешний скрипт и iframe, а CSP их запрещает (`script-src 'self'`). Значок G вписан в разметку (`img-src` и так допускает только свои и `data:`).
- «Соединить аккаунты» в задании не описано: сделана пустая строка с недоступной кнопкой «Скоро». Что именно соединять (например, аккаунт с паролем и аккаунт Google), решает владелец.
- Отображаемое имя не связано с никнеймом для входа.
