# Кэшбэк

Читать при правках раздела «Кэшбэк», истории, сообщений бота (`/cashback`, ответ по магазину, обучение), выгрузки магазинов. Общие ограничения, карта файлов, парные правила — `PROJECT_NOTES.md`.

## Данные
- Документ на пользователя: `doc:<id аккаунта>` (hash `{d, v}`: `d` — JSON, `v` — версия). `readDoc`/`loadDoc`/`writeDoc` в `api/_lib.js`; запись только при совпадении версии (CAS, Lua в `api/_db.js`); бот читает документ привязанного аккаунта (`loadDoc(uid)`, `uid` из `accountOfTelegram`).
- Формат: `{ months: { 'YYYY-MM': [{bank, items:[{cat, pct}]}] }, custom: [строки], rev: { часть: номер } }`; банк в месяце не повторяется. Части (`PART_RE`): `YYYY-MM` и `custom`, у каждой свой счётчик `rev`. Старые имена частей `YYYY-MM:человек` и месяцы старого формата (объект `{zhanna, denis}`) отбрасываются (`clean`, `cleanRev`; решение владельца 2026-10-04: тестовые данные сброшены, миграции нет).
- Проверка (`clean`): справочники `BANKS`, `CATS`, `PCTS`; до 60 строк на банк, до 30 своих категорий, до 60 месяцев.
- Справочник банков (13, порядок в списке «Банк» тот же): `otp`, `alfa`, `vtb`, `halva`, `sber`, `tbank`, `yandex`, `gazprom`, `ozon`, `raif`, `mts`, `otkritie`, `psb`. Менять только по просьбе владельца. Новый банк — в четырёх местах: `BANKS` в `api/_lib.js` (id), `BANKS` в `js/cashback/state.js` (`n` название, `m` буква на случай, если логотип не загрузился, `f` необязательный цвет), `BANK_NAMES` в `api/_bot.js`, файл `logos/<id>.svg` (квадрат с фоном, `width`/`height` 28; вставляется через `<img>`). Сверка — `tests/banks.test.mjs`. Id не переименовывать: он хранится в документах и копиях.

## API
- `GET /api/data` → `{id, name, tz, tzSet, data, rev, partner}` (без сессии 401). `partner`: `{linked:true, name, data:{months}}` (кэшбэк соединённого аккаунта, только просмотр; имя `''` если не задано) или `{linked:false}`. Партнёра определяет только `partnerAcc` (полная пара); id, версии и свои категории партнёра сайту не уходят. Команд Redis: без связи 3, со связью 6.
- `PUT /api/data` с `{parts: {ключ: {base, value}}}`. `base` не совпал с `rev` — `409 {error:'conflict', parts, data, rev}`; при гонке в Redis до 4 повторов, затем `409 busy`. Новые месяцы создаются только в окне «прошлый … +2 месяца» (`monthWindow`), существующие менять можно всегда.

## Сайт (`js/cashback/`)
- `state.js` (справочники, состояние `C`: `data`, `rev`, `dirty`, `conflict`, `partner`; `changedParts`), `view.js` (`colHtml`, `compactHtml`, `histHtml`, `customHtml`, `colsHtml`, `render`), `index.js` (`save`, `flush`, `refresh`, конфликты, режим правки; для `main.js`: `startSession`, `finishBoot`, `toGuest`, `onVisible`, `onHidden`, `pairChanged`, `nameChanged`).
- Автосохранение через `SAVE_MS` = 1800 мс (каждая запись = чтение + запись в Redis); при уходе со вкладки и закрытии — сразу с `keepalive`. `refresh`: при входе и смене месяца сразу, при возврате на вкладку и переходе на «Кэшбэк» не чаще `REFRESH_MS` (5 минут, `fresh('cb')`) и только без несохранённых правок, записи, режима правки и конфликта. Конфликты `409` остаются защитой.
- Режим правки: снимок `snap`, «Сохранить» и «Выйти без сохранения». Два вида: блоки (колонка банков за месяц) и компактный (по категориям: значки банков и процент); выбор в localStorage `view`, тема — `theme`. Подсветка (`hl`, `compactHtml`) только при двух и более записях категории: лучший процент `best`, остальные `dim`. «Скопировать из текущего месяца» копирует месяц целиком. С 25-го числа (МСК) предлагается заполнить следующий месяц.
- Партнёр: `C.partner` = `null` или `{name, months}` (`normPartner`; пустое имя — «Helper User»), отдельно от `C.data`: в правку, сохранение и снимки не попадает, `PUT` шлёт только свои части. При связи каждый месяц (текущий, следующий, история) — две колонки: слева своя (подпись `accName()`), справа партнёра без правки («Пусто», если месяц не заполнен); подсветка считается внутри колонки. В режиме правки колонки партнёра нет, история остаётся в две колонки. Обновление приходит в том же `GET /api/data` (те же `REFRESH_MS`); `pairChanged(linked)`: разрыв убирает колонку сразу, соединение делает один `GET /api/data` и берёт только `partner`. Без связи разметка прежняя.
- Гость: документ в localStorage `g-cb` (тот же формат с `rev`); `js/local.js` отвечает с тем же контрактом (проверка значений, версии частей, `409`), раздел об этом не знает: `api()` решает, куда идти. Зеркало `api/_lib.js`/`api/data.js` — парное правило. Выход и конец сессии, слияние — `notes/guest.md`.

## Сообщения бота
- **`/cashback`** («Показать кэшбэки», `BOT_COMMANDS`). Заголовок «Кэшбэки, <Месяц Год>»; одно сообщение на месяц, заполненный следующий месяц приходит вторым (заполненной считается строка с категорией и процентом); пустой месяц — «Пока не заполнено». Строится в `api/_bot.js`: `filledRows`, `catRows`, `pctLines(rows, mark)` (общая для `/cashback` и ответа по магазину), `monthText`, `cashbackTexts`; обработка в `onMessage` (`api/telegram.js`), длинный текст режет `chunkText` (3800 символов).
- Формат повторяет компактный вид сайта: категории по алфавиту (`'ru'`), под категорией строки по убыванию процента, банки с одним процентом в одной строке в порядке блоков, вместо логотипов `BANK_NAMES`; ✅ у лучшего процента, только если в категории больше одного банка. Пример: `Маркетплейсы` / `✅ 12% — ОТП` / `5% — Халва, Альфа, ВТБ`. Менять формат на сайте и в боте синхронно (парное правило).
- **Соединённые аккаунты** (только при полной паре; `loadView(uid)` в `api/telegram.js` читает свой документ, документ партнёра только на чтение и оба имени, отдаёт `pr = {me, name, doc}`; без связи `pr = null` и тексты прежние). Строки процентов с подписью: `Денис: 12% — ОТП`; одинаковый процент у обоих в одной строке через `;` (`Денис: 5% — Халва; Жанна: 5% — ВТБ`); по убыванию процента, при равенстве свои первыми; если у второго в категории записи нет, о нём ничего не пишется; «Пока не заполнено» — только если пусто у обоих. ✅ ставится, если записей больше одной с учётом обоих; подпись есть и у одиночной строки. `shopText` и `cashbackTexts` используют тот же `pr`. Расход на сообщение с чтением документа: 4 команды без связи, 8 со связью; кнопки показа списков (`so`, `sp`) документ не читают.
- **Ответ по магазину.** Любой обычный текст от человека с привязанным Telegram в личном чате — запрос; остальных, группы, другие команды и сообщения без текста бот молча игнорирует. `onMessage` читает документ, `lookup(текст, doc.custom)`, отвечает `shopText(doc, текущий месяц МСК, результат)`.
  - `api/_shops.js`: `SHOPS` — строки `[название, 'Кат' или 'Кат1+Кат2', [алиасы]]` (категории только из `CATS`), `norm` (регистр, ё → е, знаки → пробел), `oneEdit`, `lookup(query, custom, shops?)`. Латиница и кириллица связаны явными алиасами, автотранслитерации нет; склонения не распознаются. Словарь общий, псевдонимы личные.
  - Поиск тремя шагами: точное совпадение → вхождение по границам слов (от 3 символов; двухсимвольные только точно) → одна опечатка (запрос и ключ от 5 символов). Ключи: названия, алиасы, категории (`CATS` и своя `custom`). Больше одного кандидата на шаге — `ambiguous` («Не знаю точно: …»), дальше не идём; магазин и его категория в одном запросе: побеждает магазин.
  - Формат: одна категория — `Магазин · Категория` и полный список процентов (с ✅); несколько — заголовок и по лучшей строке `Категория: …`; запрос по категории — заголовок без `·`. В конце `Все покупки: лучший процент` (без ✅), если в месяце есть «Все покупки» и это не запрошенная категория. Нет категории в месяце: «У вас нет категории фастфуд» (`noCategory`; аббревиатуры как есть) или у строки `Категория: нет категории`. Месяц всегда текущий по МСК.
- **Обучение и исправление категории.** Состояние `alias` (до `ALIAS_MAX` = 200, старые вытесняются) и `pending` — `bot:<id>`, `notes/reminders.md`. Логика: `resolveShop`, `shopKey`, `disp` (`_shops.js`); `pendingPut/Get`, `aliasSet/Del`, `catChoices`, `shopKb`, `pickKb` (`_bot.js`); `onMessage`, `onShopCb`, `shopView` (`telegram.js`). Работает только по своим данным.
  - Неизвестный магазин: «Не знаю такой магазин…» и кнопки категорий: сначала заполненные в текущем месяце (по алфавиту), затем «Другая…» (остальные: порядок `CATS`, потом свои) и «← Назад»; если месяц пуст, сразу все. Выбор сохраняется как личный псевдоним, сообщение заменяется обычным ответом. Ключ псевдонима: `norm(текст)` (до 60 символов) у неизвестного, `norm(названия)` у магазина словаря (исправление действует на любое написание).
  - `resolveShop`: сначала `lookup`; категория, «не знаю точно» и пустой запрос не учатся и кнопок не получают. У найденного магазина исправление перекрывает словарь; у неизвестного псевдоним применяется, только если словарь ничего не нашёл; псевдоним на категорию, которой нет на сайте, не применяется (виден «Сбросить»).
  - Под ответом по магазину — «Не та категория» (список кнопок и «Отмена»); если по ключу есть запись, ещё «Сбросить к словарю».
  - `callback_data` `действие|id|индекс` (до 64 байт): `sk` выбрать `l[индекс]`, `so` другие, `sp` назад, `sf` не та категория, `sr` сбросить, `sb` отмена; индекс указывает в снимок списка `l` в `pending`; категория перед сохранением проверяется по сайту («Такой категории уже нет»). Нажатия только от привязанных людей в личном чате; устаревшее — «Запрос устарел», кнопки убираются; не записалось состояние — ответ без кнопок. Вебхук подписан на `callback_query` (`allowed_updates` в `api/tg-setup.js`).

## Выгрузка новых магазинов (`scripts/export-shops.mjs`)
Люди добавляют боту магазины личными псевдонимами; скрипт показывает владельцу те, которых нет в `SHOPS`. Только чтение: `SCAN bot:*` с `DB_PREFIX` (запускать с `DB_PREFIX='t:'`, пустой префикс смотрит в другую базу; скрипт предупреждает), состояние через `readBot` пачками по 20, каждый псевдоним проверяется текущим `lookup`. Отчёт: (1) новые магазины, готовые строки `['Название', 'Категория', []], // аккаунтов: N` по категориям; (2) другое написание уже известного (кандидаты в алиасы, проверять глазами); (3) исправления словаря (много аккаунтов — возможная ошибка словаря); (4) категории не из `CATS`. Запросы-категории, «не знаю точно» и совпавшие со словарём пропускаются (общее число). Флаги: `--min=N`, `--out=файл` (в `exports/`, UTF-8, существующий файл не перезаписывается; `>` в PowerShell пишет UTF-16), `--help`. В отчёте только названия, категории и числа. `exports/` в `.gitignore` и `.vercelignore`. Устройство как у `fill-dueq.mjs`: `export async function main(argv, io)`, чистая часть `layout`/`render`. Тест — `tests/export-shops.test.mjs`. Личные псевдонимы после добавления магазина в словарь остаются и занимают место в `ALIAS_MAX`; чистка потребует скрипта с сухим прогоном и `--apply`.
