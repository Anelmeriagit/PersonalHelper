# Кэшбэк

Читать при правках раздела «Кэшбэк», истории, формата сообщения бота `/cashback`. Общие ограничения и карта файлов — в `PROJECT_NOTES.md`.

## Данные
- Один документ на пользователя: Upstash Redis, ключ `doc:<id аккаунта>` (с префиксом `DB_PREFIX`), хэш `{d, v}`: `d` — JSON документа, `v` — номер версии. Чтение и запись: `readDoc/loadDoc/writeDoc` в `api/_lib.js`; запись только при совпадении версии (CAS через Lua в `api/_db.js`), «etag» в коде = номер версии, у нового документа его нет. Бот читает документ привязанного к Telegram аккаунта (`loadDoc(uid)`, `uid` даёт `accountOfTelegram`). Решение владельца 2026-10-05: старые данные кэшбэков удаляются разовым скриптом `scripts/purge-3b.mjs` (запускает владелец, порядок в `notes/CHECKLIST.md`).
- Формат (с этапа 2, один человек на аккаунт): `{ months: { 'YYYY-MM': [{bank, items:[{cat, pct}]}] }, custom: [строки], rev: { часть: номер } }`. Месяц — массив блоков по банкам, банк в месяце не повторяется.
- «Части» (parts): `YYYY-MM` и `custom` (`PART_RE` в `api/_lib.js`). У каждой части свой счётчик версии `rev`. Старые имена вида `YYYY-MM:zhanna` отклоняются (`400 bad request`).
- Серверная валидация (`clean` в `api/_lib.js`): справочники `BANKS`, `CATS`, `PCTS`; лимиты: до 60 строк на банк, до 30 своих категорий, до 60 месяцев.
- Документы старого формата (месяц как объект `{zhanna, denis}`) миграции не получили (решение владельца 2026-10-04: тестовые данные сброшены): `clean` отбрасывает такой месяц, версии вида `YYYY-MM:человек` отбрасывает `cleanRev`, свои категории остаются. Первая запись месяца начинается с версии 0.

## Гость (с 2026-10-08)
- Без аккаунта документ лежит в localStorage (ключ `g-cb`, тот же формат с `rev`); читает и пишет его `js/local.js` с тем же контрактом, что `GET`/`PUT /api/data` (проверка значений, версии частей, 409), раздел `js/cashback/` об этом не знает: `api()` в `js/api.js` решает, куда идти. Проверка значений зеркалит `api/_lib.js`/`api/data.js` (парное правило в `PROJECT_NOTES.md`). При выходе и конце сессии данные аккаунта заменяют гостевые (`guestSetCb`, `toGuest` в `js/cashback/index.js`; `toGuestMode` в `js/main.js` передаёт кэшбэк в части `snap.cb`, агент и WiFi — в `snap.ag` и `snap.wf`). При первом входе в аккаунт в этом браузере гостевой кэшбэк сливается в аккаунт (`mergeCb` в `js/local.js`, запись `PUT /api/data` из `js/merge.js`): недостающие месяц и банк копируются, банк аккаунта остаётся, свои категории объединяются; месяц вне окна, которого у аккаунта нет, пропускается (`notes/account.md`).

## Сообщение бота «Показать кэшбэки» (`/cashback`)
- Заголовок сообщения: «Кэшбэки, <Месяц Год>» (с 2026-10-03). Описание команды в меню бота: «Показать кэшбэки» (`BOT_COMMANDS`, `api/_bot.js`).
- Строится в `_bot.js`: `filledRows(doc, месяц)` (заполненные строки месяца: нужны и категория, и процент), `catRows(doc, месяц)` (строки месяца по категориям), `pctLines(rows, mark)` (строки процентов одной категории, общая для `/cashback` и ответа по магазину), `monthText(doc, месяц)`, `cashbackTexts(doc, текущий месяц)`; в `telegram.js` команду обрабатывает `onMessage`, длинный текст режет `chunkText` (по строкам, 3800 символов).
- Одно сообщение на месяц. Если следующий месяц уже заполнен, он приходит вторым сообщением.
- Формат повторяет компактный вид сайта (`compactHtml` в `js/cashback/view.js`): категории по алфавиту (`localeCompare` с `'ru'`); под категорией строки по убыванию процента; банки с одним процентом склеены в одну строку в порядке блоков месяца; вместо логотипов названия из `BANK_NAMES`.
- ✅ ставится у лучшего процента, только если в категории больше одного банка (как `multi` на сайте).
- Пример:
  ```
  Маркетплейсы
  ✅ 12% — ОТП
  5% — Халва, Альфа, ВТБ
  1,5% — Сбер
  ```
- Пустой месяц: «Пока не заполнено». Условие показа следующего месяца считает заполненной только строку с категорией и процентом. Строки «<имя>: пока не заполнено» больше нет.
- При изменении формата на сайте (`compactHtml`, `hl`) бот нужно править синхронно: логика продублирована.

## Ответ бота на название магазина
- Любой обычный текст (не команда) от человека с привязанным Telegram (`accountOfTelegram`; документ и состояние бота берутся этого аккаунта) в личном чате с ботом считается запросом. Не привязанные люди, групповые чаты, другие команды и сообщения без текста бот игнорирует молча. Обработка в `onMessage` (`api/telegram.js`): читает документ (`loadDoc(uid)`), ищет `lookup(текст, doc.custom)`, отвечает `shopText(doc, текущий месяц МСК, результат)`.
- `api/_shops.js` (с `_`: не функция Vercel): `SHOPS` — строки `[название, 'Категория' или 'Кат1+Кат2', [алиасы]]`, категории только из `CATS`; `norm` (регистр, ё → е, знаки → пробел), `oneEdit`, `lookup(query, custom, shops?)`. Латиница и кириллица связаны явными алиасами (ozon = озон), автотранслитерации нет. Словарь один на всех, псевдонимы личные (см. «Обучение»). Магазины без подходящей категории в `CATS` в словарь не входят.
- Поиск идёт тремя шагами: точное совпадение → вхождение по границам слов (от 3 символов, в обе стороны; двухсимвольные имена только точно) → одна опечатка (замена, вставка, удаление, перестановка; запрос и ключ от 5 символов). Ключи: названия, алиасы магазинов и категории (`CATS` и своя `custom` с сайта). Если на шаге больше одного кандидата, результат `ambiguous`, следующие шаги не запускаются, бот пишет «Не знаю точно: …». Магазин и его же категория в одном запросе: побеждает магазин. Неизвестный: подсказка написать название категории (и кнопки выбора, см. «Обучение»). Склонения не распознаются.
- Формат ответа: одна категория — `Магазин · Категория` и полный список строк процентов (как в `/cashback`, с ✅); несколько категорий — заголовок и по одной лучшей строке `Категория: …`; запрос по самой категории — заголовок без `·`. В конце запасная строка `Все покупки: лучший процент` (без ✅), если в месяце есть «Все покупки» и это не запрошенная категория. Категории нет в месяце (никто не заполнил): одна категория — «У вас нет категории фастфуд» (название с маленькой буквы, аббревиатуры вроде АЗС как есть; функция `noCategory` в `_bot.js`), несколько категорий — у такой строки `Категория: нет категории`. Это же при пустом месяце. «Пока не заполнено» остаётся только в сообщении `/cashback`. Месяц всегда текущий по МСК.

## Обучение бота и исправление категории
- Состояние (`alias`, `pending`) и лимиты описаны в `notes/reminders.md`. Здесь поведение. Чистая логика: `_shops.js` (`resolveShop`, `shopKey`, `disp`), состояние и кнопки: `_bot.js` (`pendingPut/Get`, `aliasSet/Del`, `catChoices`, `shopKb`, `pickKb`), обработчики: `telegram.js` (`onMessage`, `onShopCb`, `shopView`).
- Неизвестный магазин: ответ «Не знаю такой магазин…» плюс кнопки категорий. Сначала те, где в текущем месяце кто-то заполнил кэшбэк (по алфавиту), затем «Другая…» со всеми остальными (порядок `CATS`, потом свои с сайта) и «← Назад». Если в месяце ничего не заполнено, сразу все категории. Выбор сохраняется как **личный псевдоним** (`alias` в `bot:<id>`), действует только для этого аккаунта; сообщение заменяется обычным ответом.
- Ключ псевдонима: у неизвестного запроса `norm(текст)` (до 60 символов); у магазина из словаря `norm(его названия)`, поэтому исправление действует на любое написание (опечатка, латиница, алиасы). Название для показа у неизвестного: текст пользователя с заглавной буквой.
- Порядок поиска с псевдонимами (`resolveShop`): сначала `lookup` по словарю и категориям. Категория, «не знаю точно» и пустой запрос не учатся и кнопок не получают. Найденный магазин: исправление по `norm(названия)` перекрывает словарь (одна категория вместо категорий словаря). Неизвестный: псевдоним применяется, только если словарь ничего не нашёл. Псевдоним на категорию, которой уже нет на сайте, не применяется (остаётся в состоянии, виден «Сбросить»).
- Под каждым ответом по магазину («Магазин · Категория» и несколько категорий) кнопка «Не та категория»: свежий список категорий тех же кнопок, внизу «Отмена» (возвращает прежний ответ). Если по ключу есть запись в `alias`, добавляется «Сбросить к словарю» (убирает запись; у выученного неизвестного после сброса снова «не знаю» с кнопками). Допущение: сброс показывается и у выученного неизвестного, не только у исправления словаря.
- Запрос по категории и «Не знаю точно» отвечают без кнопок и без записи в состояние.
- callback_data: `действие|id|индекс`, не длиннее 64 байт, текста категории нет. Действия: `sk` выбрать `l[индекс]`, `so` другие, `sp` назад, `sf` не та категория, `sr` сбросить, `sb` отмена. Индекс указывает в снимок списка `l`, сохранённый в `pending`, а не в текущий список сайта. При выборе категория проверяется ещё раз по сайту («Такой категории уже нет»).
- Нажатия обрабатываются только для людей с привязанным Telegram (`accountOfTelegram`) и только в личном чате; остальные молча игнорируются. Устаревший или вытесненный запрос: «Запрос устарел», кнопки убираются. Если состояние не записалось, ответ уходит без кнопок.
- Для `callback_query` вебхук должен быть подписан в `allowed_updates` (`api/tg-setup.js`: `['message','callback_query']`, проверено по коду, менять не нужно).

## API
- `GET /api/data` → `{id, name, data, rev}` (`id` — id аккаунта из сессии, `name` — отображаемое имя; без сессии 401).
- `PUT /api/data` с `{parts: {ключ: {base, value}}}`. Если `base` не совпал с `rev` на сервере — `409 {error:'conflict', parts, data, rev}`. При несовпадении версии в Redis до 4 повторов, затем `409 busy`. Новые месяцы создаются только в окне «прошлый … +2 месяца», существующие менять можно всегда.

## Фронтенд
- `js/cashback/state.js`: справочники, состояние `C`, чистые функции над данными (`peek`, `list`, `changedParts`, ...); `js/cashback/view.js`: разметка (`colHtml`, `compactHtml`, `histHtml`, `customHtml`) и `render()`; `js/cashback/index.js`: `save/flush/refresh`, конфликты, режим редактирования, события и функции для `main.js` (`startSession`, `finishBoot`, `loggedOut`, `onVisible`, `onHidden`).
- Состояние (поля объекта `C` в `js/cashback/state.js`): `data`, `rev`, `dirty` (изменённые части), `conflict`. Автосохранение через `SAVE_MS` = 1800 мс после правки (меньше записей: каждая = чтение + запись в Redis); при уходе со вкладки или закрытии страницы (`leaving`) сохранение сразу с `keepalive`; если запись уже идёт, а за ней осталась правка, следующая отправка уходит с `keepalive`, когда вкладка скрыта. Обновление с сервера (`refresh`): при входе и при смене месяца сразу, при возврате на вкладку и при переходе на страницу «Кэшбэк» не чаще раза в `REFRESH_MS` (5 минут, `js/api.js`; метка `fresh('cb')`), только на странице «Кэшбэк», и не пока есть несохранённые правки, идёт запись, режим правки или конфликт. Конфликты по `rev` (409) остаются защитой.
- Режим редактирования: снимок `snap`, `changedParts()`, кнопки «Сохранить» и «Выйти без сохранения».
- Один человек: на месяц одна колонка `.col` (внутри `.cols`, без заголовка с именем). Подсветка (`hl`, `compactHtml`) только при двух и более записях категории: лучший процент `best`, остальные `dim` (уровня `good` больше нет). Кнопка «Скопировать из текущего месяца» (`data-m=copy`) копирует месяц целиком; у элементов правки атрибут `data-mo` (месяц), `data-p` нет.
- Два вида: блоки (колонка банков за месяц) и компактный (по категориям: значки банков и процент). Выбор хранится в localStorage (`view`), тема тоже (`theme`).
- С 25-го числа (МСК) показывается предложение заполнить следующий месяц, можно скопировать из текущего.
