# Гостевой режим и слияние данных при входе (читать при правках гостя, `js/local.js`, `js/merge.js`, выхода, конца сессии, `toGuestMode`)

Свойства разделов у гостя (ключи localStorage, зеркала проверки, QR, уведомления) — `notes/cashback.md`, `notes/agent.md`, `notes/wifi.md`; вход, меню, настройки — `notes/account.md`; сессия — `notes/session.md`.

## Решения владельца (2026-10-08)
- Окно приветствия один раз, затем сайт без входа; вход через Google необязателен; регистрации и входа по паролю нет.
- Кэшбэк, агент и Wi-Fi у гостя работают, данные только в localStorage этого браузера: на сервер не уходят, при очистке браузера пропадут, между устройствами не синхронизируются. «Напоминания» и Telegram-бот только с аккаунтом (гость видит предложение войти, `#remGuest`).
- При входе гостевые данные автоматически сливаются в аккаунт; после выхода данные аккаунта заменяют гостевые в браузере (предупреждения для iOS не нужно).

## Устройство
- `boot()` (`js/main.js`) спрашивает `GET /api/data` через `net()`: 401 — гость (запрос без cookie отвечает 401 до Redis, 0 команд), 200 — аккаунт. `api()` (`js/api.js`): с аккаунтом (`S.acct`) запрос идёт на сервер, у гостя отвечает `js/local.js` из localStorage тем же контрактом; пути, которых у гостя нет, получают 401, `authFail()` для гостя ничего не делает.
- Выход: параллельно свежие `GET /api/data`, `/api/agent`, `/api/wifi` (пока сессия жива), затем `logout`; данные аккаунта записываются как гостевые (`guestSetCb`, `guestSetAg`, `guestSetWf`) и заменяют прежние; несохранённая правка агента берётся из памяти (`agPending`); часть, чей запрос не удался, остаётся как была. Данные аккаунта остаются в браузере (на общем компьютере другой аккаунт Google получит их через слияние); если решение изменится, чистить гостевое хранилище при выходе.
- Конец сессии на ходу (401 раздела): данные берутся из памяти страницы вместе с несохранёнными правками, сверху сообщение про гостевой режим. Удаление аккаунта гостевые данные не трогает.
- `toGuestMode({cb, ag, wf})` передаёт части отдельно: часть без данных оставляет гостевые как были; `wf: null` — у аккаунта сетей нет, гостевые удаляются. Сети Wi-Fi при 401 доступны, только если раздел открывался за сессию (`wfLast`, `wfPend` в `js/wifi.js`); иначе гостевые остаются.
- Пояс гостя — пояс устройства: `guestTzUse` в `js/main.js` определяет его при открытии и возврате на вкладку, строки агента пересчитываются по `at` (`guestTzSync`, метка `g-tz`). Выход переносит время аккаунта в пояс устройства, слияние — время гостя в пояс аккаунта. Окна выбора пояса у гостя нет (`notes/reminders.md`, «Часовые пояса»).

## Слияние при входе через Google
- `boot()` → `openAcct(j)` вызывает `mergeGuest(j)` (`js/merge.js`) до открытия разделов; правила и метка в `js/local.js` (`guestDump`, `mergeCb`, `mergeAg`, `mergeWf`, `guestMerged`, `guestMark`). `GET /api/data` для метки отдаёт `id` аккаунта.
- Метка `g-mg` (localStorage): id аккаунтов, с которыми в этом браузере уже сливали (последние 20); ставится после успешного слияния и сразу, если гостевых данных нет (вернувшиеся после выхода данные обратно не сливаются).
- Правила: аккаунт побеждает, гость заполняет пробелы. **Кэшбэк:** месяц и банк, которых нет в аккаунте, копируются; банк аккаунта в том же месяце остаётся; свои категории объединяются (аккаунт первым, без учёта регистра, до 30; регистр как у аккаунта). **Агент:** строка гостя с тем же названием (без учёта регистра, по порядку) совпадает со строкой аккаунта: остаётся строка аккаунта, а если у неё нет времени, берётся время гостя; строки без пары добавляются в конец, пока их не 12. **Wi-Fi:** сети гостя, которых нет у аккаунта (`notes/wifi.md`), добавляются, пока не станет 5.
- Запись напрямую на сервер через `net()` (не `api()`: сессия уже есть, 401 не переводит в гостя). Три части независимо и параллельно: `PUT /api/data` только изменёнными частями с версиями из ответа входа; `GET`/`PUT /api/agent`, только если у гостя есть эта часть; `GET /api/wifi`, затем `PUT /api/wifi` с `add:true` по сети. Нет связи, 5xx, 401, 409, 429: метка не ставится, слияние повторится при следующем открытии сайта (повтор безопасен). Любой другой отказ (например 400) окончательный: метка ставится.
- На экране: при первом входе с гостевыми данными в кэшбэке сверху на 6 секунд «Данные из гостевого режима добавлены в аккаунт.» (`cbNote`); если записывать нечего, сообщения нет. Гостевые данные в браузере после слияния не меняются.
- Пределы: (1) месяц гостя старше «прошлого», которого у аккаунта нет, сервер создать не даёт (окно «прошлый … +2» в `PUT /api/data`, зеркало в `js/local.js`): он пропускается и пропадёт при выходе; (2) строки гостя без времени и без пары добавляются тоже; (3) пока слияние не удалось, оно повторяется при каждом открытии сайта; (4) аккаунт, отмеченный в `g-mg`, больше не получает гостевых данных, даже если они изменились.

## Ссылка «Соединить аккаунты» у гостя
Гость, открывший `/?join=<токен>`, ничего не соединяет: адрес очищается, токен лежит в localStorage `pj` до суток, гостю предлагается войти через Google; после входа `pair-join` уходит сам. Слияние гостевых данных идёт первым и от соединения не зависит (`notes/account.md`).
