# Personal Helper — заметки для Claude

Читать первым. Затем по индексу «Какие заметки читать» открывать только нужные файлы из `notes/`. Обновлять после значимых правок: строка в «Журнал»; если изменились данные, API, карта модулей или ограничения, то ещё и нужный файл в `notes/` или это ядро. Файлы, помеченные «не просмотрено», перед правкой нужно запросить.

## Что это
Личное приложение (PWA) «Personal Helper»: переходит от версии для двоих к публичной мультипользовательской. С этапов 2 и 3b всё личное у каждого аккаунта: кэшбэк, напоминания, агент, WiFi и состояние бота. Бот работает только с аккаунтами, к которым привязан Telegram. Этапы: 1–4 готовы (аккаунты, личные данные, бот и cron на аккаунтах, резервная копия Redis), 5 — доработка функционала (сейчас: меню пользователя, настройки аккаунта, вход через Google, удаление аккаунта; `notes/account.md`), 6 — запуск. Четыре раздела:
- **Кэшбэк** — в каком банке какие категории кэшбэка выбраны на текущий и следующий месяц, плюс история прошлых месяцев (один человек на аккаунт).
- **Напоминания** — личные, две колонки: «Повторяющиеся» (слева) и «Временные» (справа, разовые); создаются на сайте, у каждого вкл/выкл. Над колонками блок «Telegram»: привязка аккаунта к боту. Отправка в Telegram-боте @PersonalHelper1Bot в тот Telegram, что привязан к аккаунту.
- **WiFi** — своя сеть пользователя (вводится на вкладке, хранится в его аккаунте): QR-код для подключения камерой телефона, показ/копирование пароля и печатная страница A4.
- **Агент** — список строк «приложение — время сброса токенов», порядок меняется перетаскиванием, время по Москве. Ближайший сброс подсвечен, в момент сброса сайт показывает уведомление браузера (пока он открыт). В Telegram по этому времени ничего не шлётся.

Хостинг: Vercel, регион fra1, **тариф Hobby**: cron только раз в сутки (в `vercel.json` два ежедневных вызова), поэтому ничего, что должно сработать в точную минуту, сервер сам отправить не может. Для времени сброса используется уведомление в браузере, а не Telegram. Если понадобится Telegram или пуш при закрытом сайте, нужен тариф Pro (cron `*/10 * * * *`) или внешний планировщик (например, cron-job.org) с запросом к `/api/cron`.

## Стек
- Фронтенд: статика без сборки. `index.html`, `style.css`, `theme.js`, `sw.js` и ES-модули в `js/` (точка входа `js/main.js`, подключена как `<script type="module">`; внутри модулей прежний стиль ES5: `var`, `function`). HTML собирается строками и вставляется через `innerHTML`, все значения проходят через `esc()`.
- Бэкенд: Vercel Functions в `api/` (ESM, Node 22). Единственная зависимость — `@vercel/blob` (нужна только `api/_backup.js` для резервных копий, этап 4). QR генерирует собственный код `api/_qr.js` (без пакетов).
- Хранилище: всё в Upstash Redis через REST (`api/_db.js`, без пакетов; запись по версии через Lua, CAS): аккаунты и привязка Telegram, документ кэшбэков (`doc:<id>`), агент, WiFi, личные напоминания (`rem:<id>`), состояние бота (`bot:<id>`). Vercel Blob в `api/` используется только в `_backup.js`: приватные зашифрованные копии Redis (`backup/`, этап 4; см. `notes/backup.md`). Данные пользователей в Blob не пишутся. Старые файлы `bot/state.json` и `agent/rows.json` (если остались) лежат неиспользуемыми, первый удаляет скрипт чистки.
- Бот: вебхук `api/telegram.js`, рассылка `api/cron.js`, логика бота и состояние `bot:<id>` в `api/_bot.js`, личные напоминания и их расписание в `api/_rem.js`, словарь магазинов и поиск в `api/_shops.js` (псевдонимы личные), разовая настройка вебхука `api/tg-setup.js`.

## Ограничения (важно при правках)
- CSP в `vercel.json` строгая: **нет inline-скриптов и inline-обработчиков**, нет внешних скриптов и стилей, inline-атрибуты `style` разрешены, картинки только свои и `data:`.
- Без сборщика и фреймворков.
- Проект станет публичным (решение 2026-10-04): в репозитории, заметках и тестах только имена переменных окружения, без значений секретов, паролей, токенов и хешей. `README.md` удалён.
- Написание: по-русски «кэшбэк», по-английски «cashback» (идентификаторы `cashback`, `/cashback`, `js/cashback/`). Другие варианты написания не использовать.
- Данные пользователей пишутся только через `writeDoc` (документ кэшбэков), `writeRec`/`dropRec` (агент `agent:<id>`, WiFi `wifi:<id>`), `mutateRem` (напоминания `rem:<id>`), `mutateBot` (состояние бота `bot:<id>`) и функции `api/_acc.js` (CAS по версии).
- Секреты только в переменных окружения Vercel (список имён в `notes/CHECKLIST.md`), в коде не хранить.
- Состояние бота пишется только через `mutateBot(id, fn)`, напоминания только через `mutateRem(id, fn)`: в обход, мимо `normBot`/`normRem`, не писать, иначе потеряются поля. Новое поле бота сначала добавляется в `normBot` (`_bot.js`), новое поле напоминаний — в `custom1`/`rec1`/`normRem` (`_rem.js`).
- Новые стили добавлять в конец `style.css`, используя существующие классы.
- Расход команд Redis (Upstash Free: 500 тыс. в месяц, каждая команда в pipeline и в транзакции считается отдельно): сайт обновляет раздел при возврате на вкладку не чаще раза в `REFRESH_MS` (5 минут, одна константа в `js/api.js`, метки `fresh(раздел)`/`stamp(раздел)` в `S.at`); сразу, без паузы, обновление идёт при входе, переходе на раздел, смене месяца, после конфликта сохранения и в опросе привязки Telegram. Автосохранение кэшбэка и агента через 1800 мс. Новые запросы к API на клиенте и новые команды на сервере добавлять с оглядкой на этот расход; число команд эндпоинта проверять в тесте через `__cmdLog` заглушки Redis (`tests/redis.mjs`). Резервная копия (`api/_backup.js`) читает известные виды ключей по типу одной командой на ключ, временные `rl`, `tgt`, `tgp` не копирует, а новую копию делает раз в 7 суток (`notes/backup.md`); новый вид ключа в коде добавлять в `KNOWN` или `TEMP` там же.
- Тариф Hobby: не больше 12 функций в `api/`. Сейчас 11 (все файлы без `_`: `data`, `reminders`, `custom`, `recurring`, `agent`, `wifi`, `cron`, `telegram`, `tg-setup`, `auth`, `tglink`). Вспомогательные модули называть с `_` (`_lib`, `_bot`, `_qr`, `_shops`, `_db`, `_acc`, `_rem`): проект с такими файлами деплоится, значит они в счёт не идут; новый эндпоинт без `_` занимает последнюю свободную ячейку. Разовые скрипты лежат в `scripts/` (не в `api/`), в счёт не идут и исключены в `.vercelignore`.
- Скрипты, удаляющие данные: по умолчанию сухой прогон, `--apply` с подтверждением вводом `DELETE`, в выводе только числа и начало id; шаблон — `scripts/purge-3b.mjs`.

## Сессия и вход
- Мультипользовательский вход (этап 1, 2026-10-04): аккаунты в Redis, `api/_acc.js` + `api/auth.js` (`login`, `register`, `logout` одним эндпоинтом; привязка Telegram — `api/tglink.js`). Никнейм: латиница, цифры, `_ . -` (3–24). Пароль от 8 символов, scrypt.
- Лимиты: 10 неудач на адрес и 10 на никнейм за 15 минут, 10 регистраций в час с адреса. Регистрация по паролю включается `REG_OPEN=1`; вход через Google (`notes/account.md`) от неё не зависит; всего аккаунтов `MAX_USERS` (по умолчанию 500). Ключи Redis с префиксом `DB_PREFIX`.
- Сессия: cookie `cb_session` хранит id аккаунта (32 hex), подпись HMAC только от `SESSION_SECRET` (≥32 символов), 30 дней со скользящим продлением. Смена `SESSION_VERSION` разлогинивает все устройства. `AUTH_HASH` больше не используется. Любой 401 на сайте ведёт на экран входа.
- Кэшбэк, напоминания, агент, WiFi и состояние бота личные: эндпоинты работают только с аккаунтом из сессии. Переменные `WIFI_*` больше не читаются.
- `AUTH_USER` код больше не читает; переменную удалить из Vercel после подтверждения владельца (`notes/CHECKLIST.md`).
- Привязка Telegram (этап 3a, 2026-10-04; с 3b от неё зависят рассылка и ответы бота): на вкладке «Напоминания» блок «Telegram»; `POST /api/tglink` выдаёт одноразовую ссылку `https://t.me/<бот>?start=<токен>` (10 минут, не больше 5 ссылок за 10 минут на аккаунт), бот по `/start <токен>` связывает Telegram с аккаунтом. Один Telegram привязан к одному аккаунту. Ключи Redis (с `DB_PREFIX`): `tgt:<хеш токена>` → id аккаунта (TTL), `tgp:<id>` → хеш последней ссылки, `tg:<id>` → `{tid, chat, un, at}`, `tgu:<tid>` → id аккаунта, `tgs` → множество id аккаунтов с привязкой (обход для cron). Токен нигде не хранится, только sha256. Функции в `api/_acc.js`: `createLinkToken`, `bindTelegram`, `getLink`, `unlinkTelegram`, `accountOfTelegram`, `linkedIds`. Подробности — `notes/reminders.md`.

## Как работать с проектом
- В начале задачи: прочитать этот файл и нужные файлы из `notes/` по индексу, назвать, какие файлы кода нужны (списком, очень кратко), не просить весь репозиторий. Фронтенд по модулям: просить только нужные файлы из `js/` по карте выше.
- После своих правок пользователь коммитит, пушит и нажимает Sync now на репозитории в знаниях проекта.
- Пользователь работает в Windows (PowerShell): вместо `grep` предлагать `Select-String -Encoding utf8`, вместо `curl` писать `curl.exe`.
