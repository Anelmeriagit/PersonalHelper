# Personal Helper — заметки для Claude

Читать первым. Затем по индексу «Какие заметки читать» открывать только нужные файлы из `notes/`. Обновлять после значимых правок: строка в «Журнал»; если изменились данные, API, карта модулей или ограничения, то ещё и нужный файл в `notes/` или это ядро. ## Что это
Личное приложение (PWA) «Personal Helper»: переходит от версии для двоих к публичной мультипользовательской. С этапов 2 и 3b всё личное у каждого аккаунта: кэшбэк, напоминания, агент, Wi-Fi и состояние бота. Бот работает только с аккаунтами, к которым привязан Telegram. Этапы: 1–4 готовы (аккаунты, личные данные, бот и cron на аккаунтах, резервная копия Redis), 5 — доработка функционала (сейчас: меню пользователя, настройки аккаунта, вход через Google, удаление аккаунта; `notes/account.md`), 6 — запуск. Без входа сайт открывается гостем (этап 5, гостевой режим, 2026-10-08): окно приветствия один раз, затем кэшбэк, агент и Wi-Fi без аккаунта, данные в localStorage браузера (`js/local.js`), на сервер и в Redis ничего не уходит; напоминания и Telegram-бот только с аккаунтом. Вход один — через Google, кнопка в шапке, необязателен; при первом входе в аккаунт в этом браузере гостевые данные сливаются в него автоматически (`js/merge.js`). Подробности и состояние частей — `notes/guest.md`.
«Соединить аккаунты» (этап 5, решение владельца 2026-10-08, делается по частям; план и контракт — `notes/account.md`): два аккаунта по одноразовой ссылке-токену соединяются, видят кэшбэк друг друга только на просмотр, у обоих появляется рамка «Общие» в напоминаниях. Готово: все 5 частей (сервер связи; настройки: «Поделиться», открытие ссылки `/?join=<токен>`, «Разорвать»; кэшбэк партнёра: `GET /api/data` отдаёт ещё `partner`, на сайте две колонки только на просмотр; общие напоминания на сервере: запись `shr:<id>:<id>`, `shared` в ответах `/api/reminders`, `/api/custom`, `/api/recurring`, рассылка cron по галочкам каждого); сайт: рамка «Общие» на вкладке «Напоминания», у каждого общего две галочки (своя и партнёра), любую меняет любой из двоих, разрыв связи удаляет общие напоминания у обоих (часть 5).
Часовые пояса (этап 5, решение владельца 2026-10-12, делается по частям; план и контракт — `notes/reminders.md`, «Часовые пояса»): у каждого аккаунта свой пояс, общие напоминания пары считаются по настенным часам каждого. Готово: часть 1 (хранение пояса: `tz` у аккаунта, действие `set-tz`, `api/_tz.js`), часть 2 (напоминания, индекс `dueq`, cron и обработчики считают время по поясу аккаунта) часть 3 (месяц кэшбэка в боте по поясу аккаунта, окно новых месяцев `PUT /api/data` с запасом ±14 часов, агент: `nextAt` по поясу, `at` абсолютный, при смене пояса ч:мин строк пересчитываются) и часть 4 (сайт: `js/tz.js`, `js/time.js` по поясу режима, окно настроек со списком поясов, подсказка при расхождении с устройством, гость по поясу устройства). Часть 5 (заметки и порядок): расписание QStash `*/10 * * * *` на 24 часа и запасного cron-job.org круглые сутки (код не менялся, задаётся в консолях; `notes/DEPLOY.md`, «Порядок деплоя: часовые пояса, часть 5»), лимиты Upstash сверены (`notes/reminders.md`, «Лимиты Upstash»). Остаётся боевая проверка двух поясов (`notes/CHECKLIST.md`, «Часовые пояса»).
Четыре раздела:
- **Кэшбэк** — в каком банке какие категории кэшбэка выбраны на текущий и следующий месяц, плюс история прошлых месяцев (один человек на аккаунт).
- **Напоминания** — личные, две колонки: «Повторяющиеся» (слева) и «Временные» (справа, разовые); создаются на сайте, у каждого вкл/выкл; напоминания в двух скруглённых рамках («Личные» и, у соединённых аккаунтов, «Общие»), в каждой повторяющиеся слева, временные справа. Над колонками блок «Telegram»: привязка аккаунта к боту. Отправка в Telegram-боте @PersonalHelper1Bot в тот Telegram, что привязан к аккаунту.
- **Wi-Fi** — сети пользователя, до 5 (вводятся на вкладке, хранятся в его аккаунте): QR-код для подключения камерой телефона, показ/копирование пароля и печатная страница A4. Общий список у соединённых аккаунтов — решение владельца 2026-10-12, делается по частям (`notes/wifi.md`, «Общий Wi-Fi»): готовы все части 1–5 (сервер: запись пары `wfs:`, выбор при соединении, копии при разрыве; сайт: окно выбора «Оставить мою / партнёра / обе»).
- **Агент** — список строк «приложение — время сброса токенов», порядок меняется перетаскиванием, время по поясу аккаунта (у гостя — устройства). Ближайший сброс подсвечен, в момент сброса сайт показывает уведомление браузера (пока он открыт). В Telegram по этому времени ничего не шлётся.

Хостинг: Vercel, регион fra1, **тариф Hobby**: cron только раз в сутки (в `vercel.json` один ежедневный вызов `?role=backup&rebuild=1`), поэтому ничего, что должно сработать в точную минуту, сервер сам отправить не может. Для времени сброса используется уведомление в браузере, а не Telegram. Если понадобится Telegram или пуш при закрытом сайте, нужен тариф Pro (cron `*/10 * * * *`) или внешний планировщик (например, cron-job.org) с запросом к `/api/cron`. Переход на внешний планировщик (QStash, запасной cron-job.org, Redis как страховка) идёт по частям, план — `notes/reminders.md`, «Переход на внешний планировщик».

## Стек
- Фронтенд: статика без сборки. `index.html`, `style.css`, `theme.js`, `sw.js` и ES-модули в `js/` (точка входа `js/main.js`, подключена как `<script type="module">`; внутри модулей прежний стиль ES5: `var`, `function`). HTML собирается строками и вставляется через `innerHTML`, все значения проходят через `esc()`.
- Бэкенд: Vercel Functions в `api/` (ESM, Node 22). Единственная зависимость — `@vercel/blob` (нужна только `api/_backup.js` для резервных копий, этап 4). QR генерирует собственный код `api/_qr.js` (без пакетов); у гостя ту же матрицу строит браузер (`js/qr.js`, парный файл).
- Хранилище: всё в Upstash Redis через REST (`api/_db.js`, без пакетов; запись по версии через Lua, CAS): аккаунты, привязка Telegram и связь двух аккаунтов (`pair:<id>`), документ кэшбэков (`doc:<id>`), агент, Wi-Fi, личные напоминания (`rem:<id>`), общие напоминания пары (`shr:<меньший id>:<больший id>`), общий список Wi-Fi пары (`wfs:<меньший id>:<больший id>`), состояние бота (`bot:<id>`), индекс cron «кому пора слать» (`dueq`, отсортированное множество; `notes/reminders.md`, «Индекс dueq»), временные ключи запусков cron (`cron:hb` пульс основного, `cron:lock` замок, `cron:bk` отметка проверки копии; `notes/reminders.md`). Vercel Blob в `api/` используется только в `_backup.js`: приватные зашифрованные копии Redis (`backup/`, этап 4; см. `notes/backup.md`). Данные пользователей в Blob не пишутся. Старые файлы `bot/state.json` и `agent/rows.json` (если остались) лежат неиспользуемыми (удалить вручную в Blob по желанию; скрипт, который удалял первый, убран 2026-10-08).
- Бот: вебхук `api/telegram.js`, рассылка `api/cron.js`, логика бота и состояние `bot:<id>` в `api/_bot.js`, личные напоминания и их расписание в `api/_rem.js`, словарь магазинов и поиск в `api/_shops.js` (псевдонимы личные), разовая настройка вебхука `api/tg-setup.js`.

## Ограничения (важно при правках)
- CSP в `vercel.json` строгая: **нет inline-скриптов и inline-обработчиков**, нет внешних скриптов и стилей, inline-атрибуты `style` разрешены, картинки только свои и `data:`.
- Без сборщика и фреймворков.
- Проект станет публичным (решение 2026-10-04): в репозитории, заметках и тестах только имена переменных окружения, без значений секретов, паролей, токенов и хешей. `README.md` удалён.
- Написание: по-русски «кэшбэк», по-английски «cashback» (идентификаторы `cashback`, `/cashback`, `js/cashback/`). Другие варианты написания не использовать.
- Данные пользователей пишутся только через `writeDoc` (документ кэшбэков), `writeRec`/`dropRec` (агент `agent:<id>`, Wi-Fi `wifi:<id>`), `mutateRem` (напоминания `rem:<id>`), `mutateShr` (общие напоминания пары `shr:…`, только после `partnerAcc`), `api/wifi.js` (общий список Wi-Fi пары `wfs:…`, только после `partnerAcc`; копия в личные записи и удаление при разрыве — `unpair` в `api/_acc.js`), `mutateBot` (состояние бота `bot:<id>`) и функции `api/_acc.js` (CAS по версии).
- Секреты только в переменных окружения Vercel (список имён в `notes/CHECKLIST.md`), в коде не хранить.
- Состояние бота пишется только через `mutateBot(id, fn)`, напоминания только через `mutateRem(id, fn)`: в обход, мимо `normBot`/`normRem`, не писать, иначе потеряются поля. Новое поле бота сначала добавляется в `normBot` (`_bot.js`), новое поле напоминаний — в `custom1`/`rec1`/`normRem` (`_rem.js`), общих напоминаний — в `scustom1`/`srec1`/`normShr` (там же).
- Новые стили добавлять в конец `style.css`, используя существующие классы.
- Расход команд Redis (Upstash Free: 500 тыс. в месяц, каждая команда в pipeline и в транзакции считается отдельно): сайт обновляет раздел при возврате на вкладку не чаще раза в `REFRESH_MS` (5 минут, одна константа в `js/api.js`, метки `fresh(раздел)`/`stamp(раздел)` в `S.at`); сразу, без паузы, обновление идёт при входе, переходе на разделы «Напоминания», Wi-Fi и «Агент», смене месяца, после конфликта сохранения и в опросе привязки Telegram. Исключение — «Кэшбэк»: при переходе на него из другого раздела данные тоже обновляются не чаще раза в `REFRESH_MS` (решение владельца, проверено им на двух устройствах). Автосохранение кэшбэка и агента через 1800 мс. Новые запросы к API на клиенте и новые команды на сервере добавлять с оглядкой на этот расход; число команд эндпоинта проверять в тесте через `__cmdLog` заглушки Redis (`tests/redis.mjs`). `GET /api/reminders` читает ещё пару: без связи 3 команды вместо 2, со связью 6 (с общей записью); cron читает только тех, кому пора, из индекса `dueq` (запуск без задач — 6 команд независимо от числа пользователей); любая запись напоминаний стоит ещё одну команду (`ZADD dueq`). `GET /api/data` читает ещё пару и документ партнёра: без связи 3 команды вместо 2, со связью 6; кэшбэк партнёра отдельным запросом не берётся, он приходит в том же ответе и обновляется в те же `REFRESH_MS`. `GET /api/wifi`: без связи 2 команды, со связью 4 (проверка пары и общая запись). Резервная копия (`api/_backup.js`) читает известные виды ключей (в том числе `dueq`, zset) по типу одной командой на ключ, временные `rl`, `tgt`, `tgp` не копирует, а новую копию делает раз в 7 суток (`notes/backup.md`); новый вид ключа в коде добавлять в `KNOWN` или `TEMP` там же.
- Тариф Hobby: не больше 12 функций в `api/`. Сейчас 11 (все файлы без `_`: `data`, `reminders`, `custom`, `recurring`, `agent`, `wifi`, `cron`, `telegram`, `tg-setup`, `auth`, `tglink`). Вспомогательные модули называть с `_` (`_lib`, `_bot`, `_qr`, `_shops`, `_db`, `_acc`, `_rem`, `_due`, `_reindex`, `_tz`): проект с такими файлами деплоится, значит они в счёт не идут; новый эндпоинт без `_` занимает последнюю свободную ячейку. Разовые скрипты лежат в `scripts/` (не в `api/`), в счёт не идут и исключены в `.vercelignore`.
- Скрипты, удаляющие данные: по умолчанию сухой прогон, `--apply` с подтверждением вводом `DELETE`, в выводе только числа и начало id; образец — `scripts/restore-backup.mjs` и общий `scripts/_cli.mjs` (прежние скрипты чистки удалены владельцем 2026-10-08).

## Парные правила (править обе части синхронно)
- Формат кэшбэка (`months: {YYYY-MM: [блоки]}`, один человек): сайт (`compactHtml`, `hl` в `js/cashback/view.js`) и бот (`_bot.js`: `filledRows`, `catRows`, `pctLines`, `monthText`, `cashbackTexts`, `isFilled`). Логика продублирована; ответ бота по магазину (`shopText`) использует ту же `pctLines`. Подробности в `notes/cashback.md`.

- Кэшбэк партнёра (`partner` в ответе `GET /api/data`, разметка в `js/cashback/view.js`) того же формата, что свой. В бот он попадает с 2026-10-11 только на просмотр и только у соединённых аккаунтов: подпись «Имя: процент — банк» у каждой строки (`catRows`/`pctLines` с `pr` в `_bot.js`, `loadView` в `telegram.js`; `notes/cashback.md`); у не соединённого аккаунта сообщения бота прежние. Это отдельная разметка от сайта (две колонки), общей логики нет: смысл подписей менять вместе. Читать документ партнёра можно только через `partnerAcc`/`partnerOf` (`api/_acc.js`), писать только свой; псевдонимы и кнопки бота остаются личными.

- Гостевой кэшбэк (`js/local.js`: `clean`, `cleanCustom`, `cleanBlocks`, окно месяцев и версии частей) зеркалит `api/_lib.js` (`clean`, `cleanCustom`, `cleanBlocks`, `PART_RE`) и `api/data.js` (PUT): менять только вместе. Справочники `BANKS`, `CATS`, `PCTS` на сайте и на сервере одинаковы; названия банков в боте (`BANK_NAMES` в `api/_bot.js`) и файлы `logos/<id>.svg` идут той же парой (`tests/banks.test.mjs`). Слияние при входе (`mergeCb`, `mergeAg` в `js/local.js`) опирается на те же `clean`, `cleanRows` и на окно месяцев `PUT /api/data`: менять вместе.

- Гостевой агент (`js/local.js`: `cleanApp`, `cleanRows`, `withAt`, `nextAt`, лимит 12 строк, ответы `GET`/`PUT /api/agent`) зеркалит `api/agent.js`; гостевой Wi-Fi (`js/local.js`: `cleanWifi`, `normNets`, `wifiString`, список сетей до 5, ответы `GET`/`PUT`/`DELETE /api/wifi`) зеркалит `api/wifi.js`; QR гостя `js/qr.js` — копия `api/_qr.js` в стиле ES5 (результат до бита тот же). Менять только вместе. Пароль Wi-Fi гостя на сервер не уходит: QR строится в браузере.

- Часовые пояса (`api/_tz.js`): время слотов, дат и месяца считается по настенным часам пояса аккаунта (`tzOf`). Парные файлы сайта: `js/tz.js` ↔ `api/_tz.js` (плюс `nextAt`, `retimeRows` ↔ `api/agent.js`, `monthWindow` ↔ `api/_lib.js`; ES5, результат тот же, `tests/tz-site.test.mjs` сверяет на 400 сутках по 16 поясам) и гостевое зеркало агента с поясом (`withAt` в `js/local.js` ↔ `api/agent.js`; у сервера пояс — необязательный последний параметр, по умолчанию Москва): менять только вместе. Месяц «сейчас» на сервере — `curMonth(tz)` (`api/_lib.js`) или `nowIn(tz).month`; для проверок окна без знания пояса — `monthWindow()`. Нового кода с зашитой Москвой не писать: брать `nowIn(tz)` и `zonedToMs(…, tz)`.

## Как работать с проектом
- В начале задачи: прочитать этот файл и нужные файлы из `notes/` по индексу, назвать, какие файлы кода нужны (списком, очень кратко), не просить весь репозиторий. Фронтенд по модулям: просить только нужные файлы из `js/` по карте выше.
- После своих правок пользователь коммитит, пушит и нажимает Sync now на репозитории в знаниях проекта.
- Пользователь работает в Windows (PowerShell): вместо `grep` предлагать `Select-String -Encoding utf8`, вместо `curl` писать `curl.exe`.
- Владелец не ставит браузер и Playwright и сам проверки интерфейса не запускает: не предлагать ему `npm i playwright`, `npx playwright install` и `node tests/smoke.mjs`. Проверки делает Claude; их устройство и какие файлы тестов просить с кодом задачи — в `notes/tests.md`. Перед выдачей: `node --check` для JS, серверные тесты, для интерфейса `smoke.mjs`. Правка только заметок или текстов без изменения разметки и логики: тесты не нужны. Непроверенное записывать в `notes/CHECKLIST.md`.
- Коммитятся и деплоятся только файлы проекта: на деплой — файлы сайта (остальное в `.vercelignore`), в репозиторий не попадают архивы, патчи, выгрузки, логи и временные файлы (`.gitignore`). Если в присланном репозитории есть лишние файлы, сказать об этом в начале задачи и дать `git rm`.
- Формат записи в «Журнале»: до трёх строк (дата, что изменено, какие файлы; отдельно «не проверялось», если это важно после деплоя). Счёт проверок не пишем. В ядре хранятся последние 5 записей, остальные переносятся в `notes/CHANGELOG.md`.
